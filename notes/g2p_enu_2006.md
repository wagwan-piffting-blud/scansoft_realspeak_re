## Summary

- **G2P is far more than letter-to-sound.** It contains:
  - all the text normalisation: numbers, dates, times, currency, units, addresses, telephone
    numbers, URLs, acronyms, roman numerals
  - the main lexicon (34,813 entries), plus 24 small special-purpose dictionaries
  - the letter-to-sound rules for OOV words
  - morphological prefix/suffix analysis and stress classes
  - the rule-based POS tagger and homograph resolver
  - post-lexical phrase rules
  - a phonetic-input parser and a custom-G2P (cg2p) plug-in hook

  CONFIRMED (code, data, rules). This resolves the stdpp_enu §8.5 INFERRED: numbers and
  abbreviations are expanded here, not in the PP.
- **The engine is the L&H multi-tier rewrite-rule machine, the same one the prosody uses.**
  It runs over five parallel byte tiers (msg types **8, 7, 9, 10, 0x10**) plus CM (0xC),
  with a capacity of 0x5dc symbols and the overflow flag at engine+0x32b. Rule program 1
  @`0x100368f0` holds 4517 rules in 236 blocks. Native C "procedures" are called from rule
  actions through a 236-entry table @`0x10036540`. CONFIRMED. That it is the same engine as
  `pros_*` (prosody_2006) is INFERRED from the identical layout.
- **Message I/O of TranscribeTts (+0x34):**
  - text section **6 is retyped to 8**, and section 8 is rewritten *in place* from
    orthography to phonemes (PM)
  - it **creates and fills 7 (GR**, a copy of the orthography), **9 (POS)**, **10 (MORPH)**,
    **0x10 (INTON, used here for text-normalisation tags)** and **0xC (CM)**
  - it reads **0x12** markers (0x8001 tn mode, 0x8003/0x8004 domain) and the **0x27** pool

  CONFIRMED
- **The lexicon is a Huffman-coded trie** over frequency-ranked letter codes. Each entry
  string `PHON#POS#FIELD3` is BPE-compressed and front-coded against the *following* entries.
  Field 3 holds the alternate pronunciation of a homograph, a verb-subcategorisation number,
  or `Z` (none). CONFIRMED by a full decode.
- **brk_InterfaceQuery is used only for custom G2P.** It is called only from
  `g2p_SetParam` (+0x24), on `"cg2p/enu/" + name`, version 1. Up to 32 can be loaded. In-text
  `ESC\domain=<name>\` (PP marker 0x8003/0x8004) activates one, and rule procedure 0x24
  dispatches to its registered callbacks. CONFIRMED

  g2p_run_prog1_tts(engine)                // 0x10002e50 → eng_run_main_cascade 0x10005400:

### 3.2 Rule bytecode

- **Layout.** `[mode @off−1][anchor @off] focus FF leftctx(reversed) FF rightctx FF action FF`.
- **Modes 1–16.** These are scan direction × anchoring × first/all/grouped. 99 means "select
  focus/context tiers"; +100 is a flag.
- **Pattern ops (0xE9–0xFF):**

  | op | role |
  |---|---|
  | literal byte | the symbol itself |
  | FD n / EA n | bind / negated variable |
  | FC / FB n | in / not in class (+0x10) |
  | FA / F9 n | in / not in class (+0x14) |
  | F8 n | feature |
  | F4 min,max | repetition (0xdc = unbounded) |
  | ED | counted repetition |
  | F5 / F6 | sequence / alternation |
  | F7 | sub-pattern |
  | EF/F1 n, EE/F0 | switch / restore tier |
  | EC | skip `~` |
  | EB | jump to focus end |

- **Actions.** A replacement string using the same ops (F8 = feature copy, FD = variable
  output), or **`FE n` = call procedure n** (`(*(prog+0x4c))[n](eng, &start, &end)`). `FE 01` =
  keep the focus (accept), `FE 02` = end the block.

CONFIRMED (`eng_match_focus` `0x10007570`, `eng_match_context` `0x10008570`,
`eng_apply_rule_action` `0x10009a10`); exact operand counts of F4/ED/F6 INFERRED. My
disassembler (`g2p_rules.py`) misaligns on some rules.

**Procedures.** Procedure n = table[n] @`0x10036540+4n`. Most entries are 29–35-B thunks
`eng_run_rule_block(eng, n, …)`, so **procedure n = block n**. The native exceptions are listed in
§4.2 and §5. CONFIRMED (`G2pProcTab` scan of all 233 entries)

## 4. Lexicons

### 4.1 Main lexicon (`lex_lookup_main` `0x10032610`; procedure 0x20)

**Lookup.**
- Input: tier 1 [s..e]. Length ≤ 32, and every byte in 0x26..0xa4 (`lex_key_chars_valid`
  `0x100334b0`).
- On a hit, field 1 → tier1 (phonemes), field 2 → tier2 (POS), field 3 → tier3 (MORPH). The
  other tiers are padded with `~` (`lex_pad_tiers_tilde` `0x10034b40`), and ws+0xc1 is set to 1.

CONFIRMED. Emulating the real function on "record" returns `rI-'kord` / `H8!` / `'rE-k$rd`.

### 4.2 Small dictionaries (24 native procedures, one shared template)

**Template.**
- Per key length L: a row of first-letter ranges.
- The remaining letters are 5-bit codes, bit-packed by `sdict_pack_key_bits` (`0x10035c20`).
- Lookup is a binary search over fixed-size records.
- Values are bit-packed offsets into a BPE string pool with its own pair table.
- Output goes to the ws tiers, with `~` padding.

Same scheme as the PP abbreviation table (stdpp §8.2). CONFIRMED for `sdict_onset_clusters`
`0x1002dc20` and `sdict_months_days` `0x10030240`. For the others, emulation confirms behaviour.

## 7. Custom G2P (cg2p)

- **Load.** ttseg param 0x13 → `g2p_SetParam` op 0. The name is limited to 0x3f characters.
  The broker gets `brk_InterfaceQuery(broker, "cg2p/enu/<name>", 1, &cls, &iface[slot])` into
  the first free slot of 32; the name goes to obj+0xa4+slot·0x40. Unload (op 1) releases it
  and clears it from the active stack. CONFIRMED
- **Activate.** PP `ESC\domain=<x>\` → 0x12 record 0x8003 with pool string x. G2P pushes the
  iface whose name == x, or NULL, onto obj+0x8a8 (depth obj+0xca8, max 256). 0x8004 pops.
  CONFIRMED
- **Register.** In `g2p_work_alloc`, each active iface gets `iface->[+0x24](0, engine)`.
  CONFIRMED. INFERRED: the cg2p writes its `{reset, apply}` function pointers into
  engine+0x3dc/+0x4dc[k] and increments engine+0x3d8.
- **Run.** `g2p_cg2p_dispatch` (`0x100135b0`, proc 0x24) is the first call in word-level
  block 0x41. It calls the hooks LIFO, each as `reset(eng)` then `apply(eng, &s, &e)`, and stops
  at the first that returns nonzero. It saves and restores the engine scan state and the
  vars. CONFIRMED
- So a cg2p is a plug-in rule module that runs inside G2P's word pass on the same tiers
  (INFERRED: domain-specific pronunciation rules). It is not a replacement lexicon lookup.
- **brk_InterfaceQuery has no other callers.** CONFIRMED: the thunk `0x10003c84` has one
  caller, `g2p_SetParam`.
