# Front end 2004 (ScanSoft) vs 2006 (RealSpeak): `g2p_enu.dll`, `stdpp_enu.dll`

**Dated 2026-10-23.** Ghidra programs `/ss_g2p_enu.dll`, `/ss_stdpp_enu.dll` (2004,
`ScanSoft\speech\components\{g2p,pp}\`) against `/rs_g2p_enu.dll`,
`/rs_stdpp_enu.dll` (2006, `...\RealSpeak\speech\components\{g2p,pp}\`) and `/rs_vf_tom_full.dll`.
All base 0x10000000. Nothing was saved; the functions created and renamed in §7 exist only in the
open session. 2006 addresses and names are those of `g2p_enu_2006.md` / `stdpp_enu_2006.md`.

Tags: **CONFIRMED** = seen in code or data, or reproduced by running the DLL's own code / an exact
decoder. **INFERRED** = reasoning from structure or content.

Scripts (all in `C:\tmp\`):
- `g2p_lex2.py`: main-lexicon decoder for both builds (`rs` / `ss` config blocks). `rs dfs` reproduces
  `g2p_enu_lex.tsv` byte for byte; `ss dfs` wrote `g2p_enu_2004_lex.tsv`.
- `g2p_lexdiff.py`: lexicon diff → `g2p_lexdiff_2004_2006.tsv` (`chg`/`add`/`del` rows).
- `g2p_emu2.py`: Unicorn harness running the small dictionaries of both builds on one shared
  candidate set → `g2p_smalldicts_both.tsv`; `fe_sdictcmp.py` diffs it.
- `fe_ss_survey.py` (headers, vtables, say-as tables, proc tables), `fe_rulecmp.py` /
  `fe_blockcov.py` (rule bytecode comparison; `fe_blockmap*.txt`), `fe_procs.py` / `fe_thunks.py`
  (native procedures), `fe_refs.py` / `fe_refs2.py` (RS table refs → SS addresses), `fe_vfhdr.py`
  (VF rule header), `flexdfa_ss.py` (SS copy of the flex emulator), `pptables_ss_abbrev.py`,
  `fe_ppcmp.py`, `fe_dis.py`, `fe_vt.py`, `fe_immscan.py`.

## Summary

- **Same engine, same source tree, regenerated data.** The 2004 g2p has the same 18-slot interface,
  the same `TranscribeTts` flow, the same rule-program header layout, the same Huffman-trie
  lexicon format and the same cg2p mechanism. The 2006 build is a **data and rule-set extension**,
  not a rewrite. CONFIRMED (§1–§3)
- **Lexicon: 34,689 (2004) → 34,813 (2006).** 34,529 entries identical, 150 changed, 134 added,
  10 removed. Changes are hand fixes (vowel corrections, stress, British `-tre`/`-oeuvre` spellings,
  RealSpeak/tech words). CONFIRMED (§2.3)
- **Rules: 3,315 rules / 162 block slots (88 used) → 4,517 / 236 (146 used).** 3,121 of the 3,315
  2004 rules have an operand-masked twin in 2006. The bulk of the +1,202 is the say-as layer: 46
  blocks 0xbe–0xeb (696 rules) plus dispatcher 0x33, with no 2004 counterpart. Program 2 (phoneme
  notation converter) is unchanged: 107 rules, 106 byte-identical. CONFIRMED (§3)
- **Say-as: 19 names (exact or `_`-tail match) → 69.** 2004 knows only address, date_*, number_*,
  spell and time_*. CONFIRMED (§3.3)
- **stdpp: same flex scanner, smaller.** 986 DFA states against 1598. The abbreviation list is
  identical (210 entries). The escape-tag set is the same minus `prompt=`. 2004 does not take bare
  `www.` as a URL. Readmode, markermode and tnmode were object state set through `SetParam` in 2004;
  2006 moved them to paramc and made `SetParam` a no-op. CONFIRMED (§4)
- **Prosody-notes check:** header +4 is the highest rule-variable index (23), not a set count. The VF
  prosody program has **12 block slots, 8 non-empty**. `prosody_2006.md`'s "23 rule sets" is wrong.
  CONFIRMED (§5)
- **Nothing voice- or Tom-specific** in either front end. No sign of Speechify/Eloquence content.
  (§6)
